The work behind the interface

What I changed and why.

The problem

The original dashboard presented rates without enough geographic context. Long layouts made it harder to compare charts, find controls and inspect detailed values.

What I rebuilt

I reorganised the app into Explore, Convert and Data views, connected a Leaflet atlas to currency selection, and refined the interface for desktop and mobile. API integration and data preparation remain in R/Shiny.

Connected interactions

Select a supported country to add or remove its currency from a comparison of up to six. Charts, map colours and exact-value tables follow the selection. Conversion, CSV export, optional 3D plots and fullscreen views offer different ways to inspect it.

Reliability decisions

Shared caches, bounded request queues, deduplication and retry backoff reduce unnecessary provider calls. Focused offline checks cover quota controls and date validation; they are not a complete security audit.

More product views: conversion and mobile

Data coverage and limits.

Historical observations are daily, not hourly. Quotes are indicative and exclude fees and buy/sell spreads. Coverage and freshness depend on the API plan. Shinyapps.io local storage is not a durable shared archive.

The map is a reviewed overview of a pinned source revision, not an automatically updated dependency graph or live telemetry. The animated guide is a simplified teaching example. Neither contacts the rate provider.

My focus: R/Shiny development, interface design, API integration, quota-aware caching and making those decisions easier to inspect.

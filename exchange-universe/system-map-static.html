Calculates cross-rates, aligns daily comparisons and builds the interactive chart widgets.

REUSE

Saved observations

Keeps current rates, currency names and daily history available for reuse.

Why this matters

Memory and local RDS files avoid fetching the same data for every interaction. Shinyapps.io local disk is not a durable shared archive.

How it connects

The app process collects completed worker results, then updates the store and writes local files. The worker does not write the cache directly.

PROTECT

Request controls

Checks whether another rate request is needed and can start. Repeated requests wait so the app avoids wasting its API allowance.

Why this matters

Backoff, recent-attempt spacing, deduplication and queue bounds reduce unnecessary requests. These limits belong to this process, not a distributed global limiter.

How it connects

Accepted work waits for the single background worker. Visitors can still see available saved rates while work is blocked.

APILAYER

External rate source

APILayer supplies current exchange rates, currency names and daily historical observations.

Why this matters

Coverage, freshness and endpoint access depend on the API subscription. A request is not a currency trade or a guarantee of a fresh market quote.

How it connects

Only the server-side worker makes these HTTPS calls. Authentication stays on the server.

FETCH

Background worker

Runs one current-rate, currency-name or history task in a separate R process.

Why this matters

callr keeps provider work separate from the interactive app process. Responses are validated; the parent store collects results and handles failures.

How it connects

Calls APILayer, then returns a result to the store. The saved-data arrow abbreviates that parent-process collection step.

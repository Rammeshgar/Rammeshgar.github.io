Monitor.

I built a separate monitor for the currency atlas. It exercises the public app, records what the browser saw and keeps failed runs available for investigation.

Open live dashboardFollow a checkSource code

The problem

A homepage can load while its conversion or export fails.

The runner follows the same controls a visitor uses.

01 / What gets checked

Two runs. Three visible lanes.

Smoke and Regression exercise different depths of the same application. Conversion has its own dashboard lane, based on checks inside the completed suites.

01 / Smoke

Every 15 minutes

HTTP readiness and Shiny session, numeric currency history, EUR-to-HUF conversion.

02 / Regression

Hourly

Smoke checks plus the currency atlas, fullscreen control, comparison table and a real CSV export.

03 / Conversion

From both suites

The displayed outcome tracks the converter assertion, rather than a third independent schedule.

Hosted schedules may start late. The monitor checks observable browser behaviour; it does not independently certify the exchange rate from its provider.

03 / Incident policy

One failure.
Not five emails.

A failed check remains visible even when an email is suppressed. The mail policy is independent of recording and dashboard publication.

04 / What remains after a run

Open the evidence, not only the status.

The same result should identify which suite ran, when it ran, what failed and where to get more detail.

Dashboard and history

The public dashboard reads the GitHub Actions run archive. Select an actual timeline dot or table row to inspect detail, screenshots and downloads when present.

Local monitoring package

A Node.js process schedules checks and serves a local dashboard. The tab can close while the process is running. The downloadable Windows package includes setup and launcher instructions, with optional SMTP.

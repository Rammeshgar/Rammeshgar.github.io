Peoples Clinic QA Suite

Quality engineering / Browser · API · CI/CD

A repeatable way to check a web workflow and keep the evidence available when a check fails.

The problem

A page can load while a login, consultation or API path still fails. Those journeys need checks that can run again and leave useful evidence.

My focus

I connected workflow validation with scheduled execution and a dashboard, so the checks and their latest states can be inspected together.

The implementation

  • Smoke checks for login, dashboard and logout.
  • UI/API regression checks for the consultation workflow.
  • Parser and AI-behavior checks with artifacts.
  • Cooldown-aware alerts for repeated failures.

What you can inspect

The dashboard shows status and execution history for each suite, including when a monitor is paused. The screenshot on this page is a historical example.

These checks cover selected behavior. They do not establish clinical accuracy or guarantee availability.

Seneschal

AI workflow tools / Windows · WSL · OpenCode

A local workspace that makes agent tasks, permissions and review visible.

The problem

Working with several AI agents creates decisions about who does what, which tasks depend on others and what an agent may change. I wanted those decisions in the interface.

My focus

I structured the workflow and directed the AI-assisted implementation: sessions, roles, access controls and a board for coordinating dependent work.

A decision in the design

A dependent task starts after its selected prerequisites finish. Each board card retains a session, and a supervisor can review the completed work. Permissions and handoffs stay visible.

What you can inspect

The public beta includes source code, releases and documentation for the Agent Board, Windows/WSL setup and local integrations. Cloud model use still depends on the selected provider.

The portfolio image is a product illustration, rather than a capture of private sessions.

Exchange Universe

Currency atlas / R · Shiny · Leaflet · ECharts · Plotly

Compare value through time. See where each currency belongs.

Explore the source-linked system map and animated guide →

The problem

The original dashboard presented rates without enough geographic context. Long layouts also made it harder to compare charts, find controls and inspect detailed values.

What I rebuilt

I reorganised the app into Explore, Convert and Data views, connected a Leaflet atlas to currency selection, and refined the interface for desktop and mobile. API integration and data preparation remain in R/Shiny.

Connected interactions

Click a supported country to add or remove its currency from a comparison of up to six. Charts, map colours and exact-value tables follow the selection. Conversion, CSV export, optional 3D plots and fullscreen views provide different ways to inspect it.

Reliability decisions

Shared caches, bounded request queues, deduplication and retry backoff reduce unnecessary provider calls. Focused offline checks cover quota controls and date validation; they are not a complete security audit.

Data boundaries

Historical observations are daily, not hourly. Quotes are indicative and exclude fees and buy/sell spreads. Currency coverage and freshness depend on the API plan. Hosting, performance and data availability remain constraints rather than guarantees.
